## Roles and evidence authority

- Terra, `gpt-5.6-terra` / medium: candidate reader and compactor, without oracle or labels.
- Sol, `gpt-6-sol` / medium: blind semantic assessment of public task, visible documents and actual answer. No expected label, gold alternative, candidate model identity, earlier score or prior judgment goes into its request.
- Independent dataset/calibration reviewer: inspect authored inputs, gold and labels before dispatch; record identity, exact file hashes, findings and resolutions. Cannot tune the candidate using holdout content.
- Astra, `gpt-6-astra` / high: protocol and difficult disagreement adjudication using exact evidence. The dataset author may clarify authored premises but must not independently certify their own labels. Use a different reviewer context for author-review separation.
- Coordinator: freezes source, prompts, configuration and criteria; collects metadata and reports. It stays unexposed to holdout semantics while tuning. Host evaluation code may read private labels for validation/scoring; this is a trusted boundary, not candidate authority.
- Owner scope decision: the current instruction is “Triển khai 5 việc để đóng phase, bàn giao và phân phối tới các agent khác nhau để làm”. Together with the previously chosen subscription route, this authorizes implementing the five closure items and closing the finite starter scope when its frozen automated gates and T14 pass. This is the coordinator's explicit scope interpretation, recorded before dispatch; it does not claim that the owner has read or individually graded the outputs. No separate human output-grading prerequisite is added to this starter scope. AI-authored or AI-reviewed records always say so; a software or AI record must not be imported as `reviewerKind: human`. Broader production or gameplay acceptance requires a separate scope decision.

Dataset-label review and output review are different artifacts. The [latest DEV report](phase-3-closure-tests-2026-09-28.md) is diagnostic evidence, not fresh holdout acceptance. Its corrected six controls are exposed regression and cannot serve as the new independent calibration check.

## Calibration check before holdout

Use the independent check in `.local/phase3-acceptance-calibration-v1`: 32 authored controls in eight new DEV families, 16 positive and 16 negative. Labels remain evaluator-private. Required coverage includes valid paraphrases, unsupported execution, false premise, conflict, missing source, wrong revision, and constraint meaning despite correct constraint IDs. Author provenance, independent label review, input/label hashes, and a content-based exposure audit are prerequisites. Schema validation is not semantic label review.

Freeze the current rubric before the blind run. Sol receives only the normal judgment request assembled from each schema-valid input; expected labels and gold are stripped by the request builder. Authoring happened without consuming current grader outputs or tuning the rubric. Independent review may correct a defective authored check before any judge run, using a new version and preserving the old artifacts. Once results have been viewed, that version is exposed regression: a changed grader/rubric requires a new untouched check.

Fixed check criteria: every planned control receives a valid judgment; agreement is at least 90% separately on the 16 positive and 16 negative controls; zero critical false accepts. With 16 controls per label stratum, at least 15 must agree, and the zero-critical-false-accept requirement takes precedence. Every required coverage category must be represented and reported; all authored correct-abstention controls must pass. Report category counts and disagreements without treating within-family mutations as independent samples. No post-run reduction of thresholds, deletion of a failing label, or selective retry. A disputed label needs actual independent adjudication; uncertainty is reported and cannot be silently marked correct.

## Fixed acceptance criteria and denominators

For each of the 12 main arm × allowance strata, a case counts as successful only if **both planned repeats** have valid output, pass deterministic bindings and the calibrated semantic assessment, and have no unresolved adjudication. Missing, malformed, timeout, refused, context-blocked or admission-blocked outcomes count as not passed in this all-planned denominator. Require at least **9/10 successful cases (90%) in every stratum**. Also require every required unanswerable/conflict case to abstain correctly in both repeats in every stratum. These conditions cannot be traded against each other.

Zero observed hard-gate violations: scope/oracle leakage, stale/revoked authority reuse, mandatory constraint/AC content loss, unsupported promotion or critical semantic false acceptance. Correct IDs alone do not satisfy constraint meaning. Positive prose unsupported by required current sources fails even if its answer happens to match. A blocked request is system behavior, not a reader's correct abstention. G failures diagnose reading separately from gathering and remain explicit; G never improves the main numerator.

Report answerability and coverage categories independently, plus all planned/scored/missing outcomes. Do not introduce a new unapproved population-reliability or 5% non-inferiority gate. Report paired F−R/F−C quality differences, repeat variation, family-level counts, and descriptive 95% intervals with the authored-sample caveat. Ten authored families do not establish production reliability; repetitions and allowances do not turn them into 300 independent cases.

Required measurements: required-source Recall@10, supporting precision, selected-context sufficiency, critical misses, requested/actual distractor exposure, canonical retention, conditional reader quality and all-planned success, compaction overhead including every summary, total reported usage, and request/task latency. Record first query after a fresh SQLite connection and repeated warm queries; call the first `connection-cold`, not disk-cold unless the OS cache was actually controlled. Latency and usage are descriptive within the operational caps; no unapproved performance threshold is invented after results. No compaction default is promoted solely for reducing bytes.
