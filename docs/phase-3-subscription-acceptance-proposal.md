# Phase 3 — Proposed subscription acceptance protocol (2026-09-28)

Status: proposed, not frozen or owner-approved. This supersedes neither historical evidence nor active release authority.

## Scope and decision requested

Close a starter infrastructure baseline on the original 20 DEV + 10 independently authored fresh holdout families. Terra (`gpt-5.6-terra`, medium) executes; Sol (`gpt-6-sol`, medium) provides independent advisory semantic assessment; Astra (`gpt-6-astra`, high) reviews disputed reasoning and the protocol. Model review is labeled as model review, never human review. Existing exposed holdout remains regression evidence and is not renamed fresh.

The owner is asked to accept the Codex subscription measurement scope: complete serialized request bytes and local admission limits, CLI-reported input/output/cached/reasoning tokens when available, invocation counts, all attempts, and end-to-end latency. Exact provider pre-count, enforced output cap, immutable backend identity and dollar cost are unavailable and remain null. This is a local/CLI context allowance comparison, not an equal-hard-provider-token-budget claim. No API key, purchase, reset credit or separate API budget is required.

Acceptance describes this authored starter challenge set only. It does not establish production reliability or a population non-inferiority margin. Report uncertainty and sample limitations, including unique families rather than treating repeated variants as independent samples.

## Proposed criteria, before fresh holdout dispatch

- Zero observed scope/oracle leakage, stale/revoked authority reuse, mandatory constraint/AC content loss, unsupported promotion, or critical semantic false acceptance.
- Independent calibration labels; at least 90% agreement and zero critical false accepts on an untouched DEV calibration-check subset. Positive, negative, paraphrase, false premise, conflict, missing-source, revision and constraint-meaning controls are mandatory. Missing judgments do not pass. Disagreements require actual adjudication.
- At least 90% case-weighted semantic success for each feasible declared arm/allowance; every required abstention scenario must be handled correctly. Failures trigger replan. Infeasible or unmeasured strata stay visible and cannot silently disappear from scope.
- Report Recall@10, supporting precision, critical misses, cold/warm time, reader quality, F/R/C paired quality differences, total compaction overhead, request/task latency and usage. All planned trials, errors and uncertain attempts remain in denominators and journals.
- T14 requires accepted T19/T11 evidence on the same pins, plus exact source/context/model-output/review/proposal/promotion/revoke trace, concurrency/replay/poison tests and survival of an unrelated branch.

## Matrix and freeze

DEV calibration first; no tuning on fresh holdout. Freeze dataset/provenance, independent label review, rubric and judge version, source/build/prompt/model/config pins, strata, task scope, all thresholds, matrix, order, caps and owner scope decision before dispatch. Use three explicitly declared local context allowances, two repeats, F/R/C1/C3; balance distractor density/evidence position across fresh cases and report this rather than claiming a crossed density effect. Post-comparison G is separate. Ten cases × three allowances × two repeats produce 240 comparisons and 60 G controls; at most 540 reader/summary calls. Freeze actual byte allowances after DEV feasibility measurements, before fresh holdout is opened.

Fresh holdout is authored and reviewed outside the implementer/tuner context. Dataset-label review and actual-output review are separate. A durable exposure ledger must record possible exposure before dispatch. Protocol/code/source changes after freeze invalidate acceptance; all prior attempts remain historical.

## Work proceeding now

Implement and test advisory meaning assessment with deterministic evidence/revision/constraint guards. Preserve the lexical scorer. Run a bounded DEV campaign and synthetic adversarial calibration, recording label provenance as unreviewed until an independent review is obtained. Prepare dependency checks and the T14 trace. These actions do not require claiming the proposal has already been approved.

No automatic Phase 4, Unity, game or active-release expansion follows this proposal. T22 remains required before game execution.
